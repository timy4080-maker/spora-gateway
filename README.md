# Spora Gateway · GATEWAY-01

Шлюз принимает непрозрачный конверт по HTTPS, сохраняет его в SQLite и передаёт по заранее настроенному маршруту. В программном стенде два шлюза, два локальных TLS Relay и два клиента SEC-01 обмениваются искусственным текстом и отдельным зашифрованным подтверждением. Между шлюзами можно отключить IP и передавать фрагменты через локальный имитатор.

## Запуск

Нужны Rust 1.100.0 и Cargo. Для полного стенда также нужны Python 3.10+, OpenSSL, исполняемые файлы SEC-01 и Relay. Linux CI собирает их из закреплённых ревизий.

```sh
cargo test --locked
cargo build --locked
python3 scripts/offline_lab.py --gateway target/debug/spora-gateway \
  --client /path/to/spora-sec --relay /path/to/spora-relay --output offline-lab.json
```

Сценарий занимает около полутора минут, создаёт временные ключи и профили, запускает процессы на loopback и удаляет временные данные. В Windows используйте пути к `.exe`; путь к OpenSSL можно передать через `--openssl`. Флаг `--manual-workers` отдаёт планирование попыток сценарию. Обычный `serve` сам выполняет IP-передачу и обслуживание хранилища.

## Граница этапа

`peer_stored` означает, что соседний шлюз сохранил конверт. `relay_stored` появляется после проверки ответа непосредственно вызванного Relay. Подтверждение обработки создаёт и проверяет клиент SEC-01. В испытании оно идёт обратно отдельной передачей. **M3 открыт.** Прошивка, serial/BLE, передача в эфире, задержки радио и работа через ретранслятор относятся к RADIO-01 и аппаратной приёмке.
