# Проверка программной части GATEWAY-01

Клиент стенда закреплён на `spora-sec@ad707a1`, Relay на `spora-relay@97d5b5c`, контракты на `Spora@79261ae`. Для сборки используются Rust 1.100.0 и Cargo.lock. Набор включает интеграционные Rust-тесты и [процессный стенд](../scripts/offline_lab.py). Локальный результат сохранён в [offline-lab.json](offline-lab.json). CI повторяет тесты на Windows и Ubuntu, полный сценарий с SEC-01 запускается на Ubuntu.

| Проверка | Наблюдаемый результат |
|---|---|
| AC-09, crash и повтор | Отдельный процесс завершается перед и сразу после COMMIT. Повтор создаёт запись только в первом случае. Одновременный приём по fake и IP в одном namespace даёт одну работу конечного Relay. Изменение поля при том же ID отвергается. На стенде процесс аварийно завершается после настоящего Relay PUT. Получатель успевает удалить серверную копию. Через 30 секунд шлюз повторяет исходный PUT, проверяет исходный receipt, обработка остаётся однократной. |
| AC-11, прямой и обратный путь | Потерянный ответ соседа оставляет отправителя в pending. Получивший шлюз хранит сообщение при остановленном локальном Relay. При отключённом обратном пути счётчик обработанных подтверждений отправителя остаётся нулевым. После восстановления клиент проверяет одно подтверждение SEC-01. Дополнительный crash между сохранением события и его применением проверяет восстановление курсора. |
| AC-13, границы и полномочия | Golden vector RadioBundle совпадает с контрактом. При 4051 байте конверта получается 4096 байт и 40 фрагментов. При 4052 байтах radio-only запрос получает 413, при разрешённом IP доступен только IP. Сборка ограничена четырьмя незавершёнными передачами на peer и шестнадцатью на шлюз. Проверены лимит одного peer, удаление просроченных частей, разные байты под одним индексом, чужой namespace, priority и попытка peer→peer. |
| AC-14, смена пути | В отдельном сценарии IP останавливается, пока доступен искусственный канал. После возврата TLS-сервиса клиент шлюза выдерживает интервал 30 секунд. Радиосборка и поздний IP PUT с тем же ID дают прежнюю запись. Большой конверт отправляется по разрешённому IP. |
| AC-19, различение restart и restore | Открываются актуальные SQLite WAL и журнал подтверждённой ревизии. Подмена только основной БД более старым снимком даёт BROKEN_RESTORE. Одновременный rollback всей машины и потеря питания контроллера выходят за границы этого опыта. |

В основном сценарии у обеих сторон есть локальный TLS Relay. У маршрутов туда и обратно разрешён только искусственный канал между шлюзами. Временный тестовый порт существующего CLI преобразует исходящий MessagePut в C-04. Он возвращает IP-worker ошибку недоступности C-03 до получения прямого ответа Relay. Gateway ACK учитывается только в статусе шлюза. Политика отказа от IP проверяется конфигурацией, весь процессный обмен идёт на одном хосте через loopback. Интеграция этого адаптера в штатный worker SEC-01 остаётся отдельным изменением клиента.

Для тестового сообщения и обратного receipt учитываются фактические байты SEC-01, 45-байтовый заголовок RadioBundle и число 105-байтовых частей. Искусственные фрагменты передаются вызовами локального порта с явно выбранным peer. В стенде отсутствуют RF-кадры, link AEAD, serial/BLE, оборудование и моделирование airtime. Эти проверки измеряют поведение хранения и доставки. Аппаратные размеры, задержки, профиль прошивки, обратный эфирный путь и вариант с ретранслятором предстоит измерить на этапе RADIO-01. M3 ожидает аппаратной приёмки.
