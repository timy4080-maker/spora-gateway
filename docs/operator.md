# Эксплуатация лабораторного шлюза

```sh
spora-gateway init --dir node-a --config gateway-a.json
spora-gateway serve --dir node-a --secrets secret-files --cert server.pem --key server.key
spora-gateway fake-step --from node-a --to node-b --reverse --duplicate
```

По умолчанию HTTPS слушает `127.0.0.1:7790`. Аргумент `--listen` задаёт другой адрес. Исполняемый пример конфигурации обеих сторон, временных токенов, сертификатов и очередей находится в [сценарии стенда](../scripts/offline_lab.py). Каждая сторона создаёт собственный каталог. Выдайте доступ к нему, каталогам ключей и ключу TLS только оператору и системной учётной записи службы. На Unix новый каталог БД получает режим 0700. В Windows настройте ACL родительского каталога до запуска.

В конфигурации укажите `gateway_id`, пределы `max_bytes` и `max_records`, словари `principals` и `routes`. Все ID и handles — 32 строчных шестнадцатеричных символа. Principal имеет роль `client` или `peer`, SHA-256 декодированного 32-байтового bearer и собственные квоты. Route задаёт владельца, разрешённые `paths`, `priorities` и неизменную цель. Для `relay` укажите service, queue, generation и IP endpoint. Для `peer` укажите ID соседнего шлюза, выданный им remote_handle и IP endpoint, если разрешён IP. Сосед принадлежит списку локально настроенных peer. Для обратного направления нужны отдельные маршруты и полномочия. Peer может сдать конверт только в разрешённый конечный Relay.

IP endpoint содержит HTTPS origin, SHA-256 PEM доверенного CA и SHA-256 декодированного bearer. В каталоге `--secrets` файлы именуются `<ca_sha256>.pem` и `<token_hash>.token`. Во втором файле лежит исходный bearer в base64url без padding. Клиент шлюза проверяет хеши, TLS 1.3, имя сервера, ID сервиса и привязку ответа к операции. Реализован заранее выбранный прямой HTTPS-маршрут. Транспорт Tor в этой сборке отсутствует.

`PUT /v1/transfers/{id}`, `GET /v1/transfers/{id}` и `POST /v1/transfers/{id}/cancel` требуют bearer владельца namespace. Структуры запросов и ответов заданы в [OpenAPI](https://github.com/timy4080-maker/Spora/blob/79261aef962f900eaf11c07cc58b6d3659859f17/docs/contracts/v0.1/openapi.json). `GET /v1/capabilities` публикует возможности сервиса.

| Команда | Действие |
|---|---|
| `install-route --dir A --handle ID --file route.json` | Добавляет маршрут существующего principal. Повтор той же привязки безопасен, смена назначения требует нового handle. |
| `forward --dir A --secrets S` | Выполняет одну готовую IP-попытку. Состояние операции проверяется через GET. |
| `fake-step --from A --to B` | Локально передаёт один готовый bundle. Ключи `--reverse`, `--duplicate`, `--limit N`, `--drop-ack`, `--disconnected` задают сбои. Доступ к обоим хранилищам требуется только оператору стенда. |
| `resume --dir A --owner ID --transfer ID` | После устранения причины возобновляет заблокированную передачу в пределах исходного срока. |
| `gc --dir A` | Освобождает истёкшие данные, затем через 24 часа записи дедупликации. Незавершённые сборки удаляются через 10 минут без прогресса или 30 минут от начала. |
| `check --dir A`, `backup --dir A --output snapshot.db` | Проверяет открытие актуального хранилища или создаёт отдельный снимок основной БД. |

При перезапуске используйте исходный каталог, включая WAL и `witness.db`. После подтверждённой записи ревизия в основной БД и отдельном журнале должна быть согласована. Если журнал новее или относится к другой инсталляции, открытие завершается с `BROKEN_RESTORE`. При утрате хранилища зафиксируйте потерю custody, используйте новый ID и новые привязки. Одновременный откат обоих хранилищ требует внешнего свидетельства актуальности.

## Пределы

До 65 536 байт конверта по IP, 4051 байта в имитаторе, предельный срок 7 суток. Квота задаётся как глобально, так и по principal. Верхние пределы 64 MiB и 10 000 активных передач; дополнительно ограничены общее число записей, размер файла и свободное место. Срок уже принятых данных сохраняется при отмене, подтверждении и повторе. Одна транспортная попытка получает 30-секундную аренду перед I/O, бюджет составляет 16 попыток на путь. После сбоя IP сосед должен пройти проверку capabilities и выдержать интервал восстановления 30 секунд. Для клиента доступны краткий статус и причина блокировки.
